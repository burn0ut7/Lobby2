# Heal and nearby repair checks

Heal Selected and Everyone target connected players only. A dead player with a retained claimed KIA slot respawns through the existing slot respawn path, at their corpse when present or their slot spawn if the corpse has been removed. Nearby uses the requester's living character and the target corpse location; a missing corpse has no known distance and is skipped with an audit entry. Spectator bodies are not healing targets.

Nearby also repairs native vehicle damage inside the selected 1–1,000 metre radius. Distance uses entity origins and includes the boundary. Repair uses the vehicle damage manager, including its hierarchy of damage zones. Destroyed wrecks are skipped and reported; no vehicle replacement, refuel or rearm is performed. Player pickers never contain vehicles. All scopes still use the production controller request, current server admin authorization and central audit logger.

Use the optional McpTestAddon in AdminMultiplayer.ent. GC_TestHealKill(playerId) arranges death only; wait for GC_TestHealSlot(playerId) to report KIA and lost possession before GC_TestAdminHeal. Check the resulting slot, native character health, client owner report and delayed possession afterward. GC_TestHealDeleteCorpse tests the missing-location case. Selected identities must come from the live player snapshot.

GC_TestHealVehicleSpawn(distanceMeters) creates up to three stock M1025 fixtures. GC_TestHealVehicleDamage(index, destroy) damages all zones or destroys the vehicle. GC_TestHealVehicleSnapshot(index) reports real damage and distance. GC_TestHealVehicleBoundary(index, distanceMeters, radiusMeters) positions and damages the vehicle, then invokes the production Nearby request in the same tick. Peer command vehicle-health accepts the spawned replication ID as its message; inspect the correlated client report after replication settles.

Verify Selected/Everyone leave damaged vehicles untouched; Nearby repairs in-range vehicles and leaves out-of-range ones damaged. Exercise ordinary peer rejection and native admin-role grant/revoke without bypassing the real action authorization. Include malformed radius and stale player identity. Keep raw MCP receipts, audit output, actual rendered menu and failures. These fixtures do not establish physical mouse interaction, every modded vehicle type or large-server performance.
