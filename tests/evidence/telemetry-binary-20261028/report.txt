Architecture: game writes uncompressed L2TB; existing external importer validates
and projects to PostgreSQL JSONB. PostgreSQL is the replay store. No archive
service, compression job, cache tier, or automatic deletion was deployed.
Existing local spool retention is unchanged. Benchmark compression files are
experiments only. The deployed importer is C:/Users/Gray/Documents/Lobby2Data/importer.

Native engine benchmark: 14 paired iterations per size, first two warmups,
alternating order, 12 measured pairs. Same generated moving-state inputs,
128 actor IDs; no game sampling, networking, database or rendering measured.
JSON recreates the prior native state/window/envelope serializer; binary uses
production Add/SaveVerified. System.GetTickCount has millisecond resolution.
128 states: JSON encode 2-3ms, binary 0-1ms; JSON 45,550 bytes
versus binary 12,892. Verified publication JSON 7-9ms, binary 5-7ms.
512 states: JSON encode 24-28ms, binary 0-1ms; JSON 181,370 bytes versus binary
49,756. Verified publication JSON 6-9ms, binary 6-8ms. This is ~72% raw state
batch reduction, NOT a whole-mission storage guarantee. Synchronous verified
file publication remains a measurable frame cost, not eliminated by binary.

Historical native corpus: 55 chunks, 3,295,048 JSON bytes -> 2,542,274 binary bytes.

import boundary; the priority is removing serialization work from the game.
Node independent decoder: 55 exact logical round trips and 14 malformed packets
rejected. Signed zero normalized in logical comparison. See benchmark reports
for timing scope; do not extrapolate them as a loaded web server benchmark.
