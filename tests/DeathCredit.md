# Respawn and bleed-out credit

User requirement: retain the last damaging player's credit when a victim bleeds out or selects Escape → Respawn, while making the death cause explicit. Each damage notification stays individual.

## Source evidence

Installed game catalogue `af6068cb44aa4c0db613213faa82a050`: `SCR_PauseMenuUI.c:778–810` calls `SCR_RespawnComponent.RequestPlayerSuicide` for confirmed Respawn and Leave Faction. `SCR_RespawnComponent.c:219–233` calls native `CharacterControllerComponent.ForceDeath`. The Lobby2 controller prefab replaces only its inherited respawn component with a subclass; no shared base-game override was added. The server resolves the requester's current body and rejects stale body IDs before marking and calling ForceDeath.

`SCR_CharacterDamageManagerComponent.c:174–189` kills a character when its blood state is destroyed. `SCR_CharacterHitZone.c:429–447` invokes that native consciousness check when blood state changes. Native `SCR_InstigatorContextData` supplies the credited hit's faction relation. Damage snapshots retain stable mission player records and are keyed to victim entity, independently of the client-only killed-from visual.
