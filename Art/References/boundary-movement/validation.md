# Hard boundary movement

2026-10-25, Workbench 1.8.0.13, Lobby2McpTests Empty_Lobby embedded host. Production handlers compiled and ran; raw runtime receipts, AO return logs, errors and original MCP screenshots accompany this note.

Cause: existing hard setup/AO called SCR_EditableEntityComponent.SetTransform. Vanilla SCR_EditableCharacterComponent.SetTransformOwner invokes PlayerTeleportedFeedback(false); vehicle override SetTransform invokes occupant feedback (long fade). Native body.Teleport itself is separate from this UI feedback. Implementation: explicit new GC_SetBoundaryTransform method, not a vanilla override. Same native owner RPC routing and ForceNodeMovement as stock transform. Body.Teleport plus zero linear/angular velocity, no GM feedback. Character orientation retained at application time, compartments protected. AO/setup keep separate authority and state. This is still a sampled position correction using the native teleport primitive, not a solid collision mesh or continuous force field. 100ms evaluator cadence unchanged. Occupied vehicles need their own observed safe pose; no character pose or generic AO marker is used for them. Missing safe pose reports unavailable rather than attempting an unsafe placement. Setup deduplicates a body's correction within an evaluator tick.
